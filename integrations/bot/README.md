# Revolution 消息入口通用接口

`core.mjs` 定义飞书与微信连接器提交给 Revolution 的统一事件字段，并在进入 DSH 任务队列前检查账号绑定、用户授权、群聊触发条件和事件去重。每条事件必须映射到一个 `revolutionUserId + workspaceId`，不会使用全局共享会话。队列提交失败时释放去重占位，允许平台重试。

已增加飞书官方 CLI 的长连接事件流与机器人发送封装 `feishu-transport.mjs`。私聊命令包括 `/当前`、`/项目 [ID]`、`/会话 [ID]`、`/新建项目 名称`、`/新建任务 名称`、`/结果`、`/停止`、`/模型 [提供商/模型ID]`。项目和会话必须出现在当前绑定用户的授权列表里；切换项目会清空旧会话。新建项目在本机个人配置目录下创建独立文件夹；新建任务创建并选中 DSH 会话，下一条普通消息开始执行。`/结果` 读取所选会话最近一次文字回复；`/停止` 调用 DSH 当前执行取消接口，已排队消息仍保留。普通消息携带选定的项目和会话进入队列；未选择会话时返回引导信息。平台适配器必须在调用 `routeBotEvent` 前验证平台签名或使用官方可信长连接；`resolveBinding`、`canAccess`、原子持久化 `dedupe`、`updateBinding` 与 `enqueue` 由产品运行时提供。不能把测试中使用的内存集合当成多用户生产存储。

Revolution 知识库插件在用户启用时启动长连接、持久化个人私聊绑定和去重记录、调用 DSH 会话并回复飞书；`/项目` 映射 DSH 工作区。启动时连接失败和事件消费者意外退出后会自动重试。已有模拟消息的单元测试；2026-10-24 在本机确认飞书凭证、事件订阅与权限预检通过，官方 CLI 可连上 WebSocket，但尚未收到真实手机飞书消息做端到端验收。本机固定预览版位于 `~/Applications/Revolution Preview.app`，版本 `0.1.4-preview.3`，登录与机器人使用同一个已绑定的飞书账号。微信入口已选定为微信对话开放平台，需取得其当前官方请求、鉴权和回复格式后实现适配器。

2026-10-24 断线修复：官方 CLI 在事件消费者标准输入收到 EOF 时会正常退出。机器人启动消费者时现在保持 stdin 管道打开，并且只有收到 CLI 的 `ready event_key` 标记才报告在线。Revolution 侧栏底部持续显示机器人在线、重连中、未启用或状态未知；知识库与设置页保留详细错误。旧预览包仍有此断线问题，需启动新构建。
