# Revolution 消息入口通用接口

`core.mjs` 定义飞书与微信连接器提交给 Revolution 的统一事件字段，并在进入 DSH 任务队列前检查账号绑定、用户授权、群聊触发条件和事件去重。每条事件必须映射到一个 `revolutionUserId + workspaceId`，不会使用全局共享会话。队列提交失败时释放去重占位，允许平台重试。

已增加飞书官方 CLI 的长连接事件流与机器人发送封装 `feishu-transport.mjs`，以及私聊命令 `/当前`、`/项目`、`/项目 <ID>`、`/会话`、`/会话 <ID>`。项目和会话必须出现在当前绑定用户的授权列表里；切换项目会清空旧会话。普通消息携带选定的项目和会话进入队列；未选择会话时返回引导信息。平台适配器必须在调用 `routeBotEvent` 前验证平台签名或使用官方可信长连接；`resolveBinding`、`canAccess`、原子持久化 `dedupe`、`updateBinding` 与 `enqueue` 由产品运行时提供。不能把测试中使用的内存集合当成多用户生产存储。

Revolution 知识库插件现已在用户启用时启动长连接、持久化个人私聊绑定和去重记录、调用 DSH 会话并回复飞书；`/项目` 第一版映射 DSH 工作区。已有模拟消息的单元测试和桌面插件启动验证，但尚未收到真实手机飞书消息做端到端验收。因此手机端暂不能当作已验证的稳定入口。微信入口已选定为微信对话开放平台，需取得其当前官方请求、鉴权和回复格式后实现适配器。
