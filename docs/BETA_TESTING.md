# Revolution 0.1.1：小范围内测发放手册

目标：先邀请 5–10 人，区分“安装阻塞”和“产品体验”，不以下载数或 CI 绿灯代替可用性验收。本项目不部署公网多租户服务，测试者在自己的电脑运行，使用自己的 API。

## 当前版本与信任边界

0.1.0 的下载 DMG 完整性和 SHA256 均通过，但包内应用签名不完整，可能显示“已损坏”。不要继续将 0.1.0 作为内测推荐包。不要覆盖旧 tag 或替换同名附件来掩盖差异。

0.1.1 改用 macOS ad-hoc 签名，并增加 codesign 校验和 Electron 窗口加载 smoke。**ad-hoc 只解决包自身签名一致性，不提供 Developer ID 身份，也不是 Apple 公证。浏览器下载后的 Gatekeeper 仍可能拦截。** 它只适合知情、能协助诊断的小范围技术测试，不应宣称“普通用户无提示安装”。正式 macOS 分发仍需 Developer ID + 公证。

Windows 当前没有发布者证书，可能出现 SmartScreen。Linux AppImage 兼容性依发行版而异。任何平台若报恶意内容、签名错误、SHA256 不一致或损坏，立即停止并反馈；不要要求测试者关闭安全软件、全局 Gatekeeper，或批量删除 quarantine 属性。

## 发放分两阶段

### A. 维护者验收：每个平台先 1 人

1. 从该版本 Actions 运行页面下载对应 Artifact（保留三天），不要混用 0.1.0 或其他提交。
2. 检查 SHA256；在独立电脑/用户环境，用普通浏览器下载、安装和启动，记录系统版本及安全提示。CI 本地启动不代替这一步。
3. 测试首次 API 配置、对话、历史恢复、一次 Workflow、产物及导出。每个环节分别记通过/阻塞，失败不得填“已验证”。
4. macOS 若仍拦截，没有证书时先把它登记为阻塞，暂停非技术用户的 Mac 发放。可邀请技术用户走源码版；源码版需要 Node/npm 和依赖安装，不是低门槛替代品，也不是安全审计的替代。
5. 三平台未全部人工通过时，可只发通过的平台，明确其他平台暂缓，不必为了“三平台齐全”扩大风险。

### B. 小范围体验：再邀请 5–10 人

1. 审核修复 PR 并合并 main，确认应用和锁文件版本为 0.1.1。
2. 在正确提交上创建 `revolution-v0.1.1` 标签并推送；流水线创建带附件的 Draft / Pre-release。
3. 将本文件中的已知限制、通过的平台和反馈入口放入 Release notes；人工验收后再 Publish。**公开仓库的 Pre-release 是公开可下载，不是访问控制意义上的封闭内测。** 真正限定访问时，先保留草稿，由维护者将已核验的包经自己管理的私有分享渠道逐人发放；不发带账号权限的页面或授权 token。离线收到的文件也需核验可信来源与 SHA256。
4. 每人发送下面的邀请函，并给出同一任务单。不要代用户填写 Key，不内置共享付费 Key，不承诺免费模型额度。
5. 在 48–72 小时后手工回访，收集安装成功率、首次对话完成率、Workflow 完成率、耗时及最困惑的一步；这不是已经设定的自动提醒。
6. 以脱敏 Issue 跟踪问题：安装阻塞优先于功能建议。修复发新版本，保留可追溯性。

## 给测试者的安装与校验

只从维护者给出的指定 Release 或可信私有分享下载：

| 系统 | 包 | 注意 |
| --- | --- | --- |
| Apple Silicon Mac | `Revolution-0.1.1-arm64.dmg` / mac ZIP | 无 Intel Mac 包；ad-hoc、未公证 |
| Windows x64 | `Revolution.Setup.0.1.1.exe` | 未做发布者签名 |
| Linux x64 | `Revolution-0.1.1.AppImage` | 按发行版验证运行依赖 |

同时下载同平台 `SHA256SUMS-*.txt`。macOS 终端：

```sh
shasum -a 256 ~/Downloads/Revolution-0.1.1-arm64.dmg
```

Windows PowerShell：

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\Revolution.Setup.0.1.1.exe" -Algorithm SHA256
```

Linux：`sha256sum Revolution-0.1.1.AppImage`。结果必须与维护者提供的校验文件一致；它验证传输一致性，不证明作者身份或无恶意代码。

macOS 复制应用到 Applications 后启动。若系统仅提示无法验证开发者，先确认来源、校验和并联系维护者；只有理解风险、来源可信时才考虑系统“隐私与安全性”提供的单应用允许选项。若显示损坏或恶意内容，停止，不使用移除隔离/全局关闭安全命令绕过。Windows 遇到安全阻塞也先记录，不要求测试者关闭 Defender。

先退出旧版再安装新包。默认数据位于 `~/.revolution`（Windows 为用户主目录下 `.revolution`）；升级前退出应用并私下备份，不上传整个目录。测试请用空白临时工作区，不连接生产仓库、私人文档或重要账号；工具调用需逐次查看权限提示。

## 10–20 分钟统一任务单

1. 记录版本、系统、架构、安装到首次可见窗口的耗时与提示。
2. 在设置 → 模型配置自己的提供商与 Key，发送“用三句话介绍你能帮助完成哪些任务”。记录成功或具体错误，不截 Key。
3. 在临时工作区发起：“使用 workflow：分别整理一个待办清单和一份 Markdown 简报，然后汇总结果。”是否真实触发受模型/能力配置影响；未触发也如实记录，不当成假运行。
4. 观察 Workflow 成员与状态，打开子会话、产物入口与导出清单；确认界面显示与实际执行一致。
5. 退出再启动，确认设置和历史是否恢复。无自动更新，后续新包需要手动安装。
6. 评分 1–5：首次配置、过程理解、结果交付。写下最想改的一件事。

模型调用按提供商收费，由测试者自行控制预算；Revolution 没有赠送额度。不要让模型在测试中执行破坏性操作、付款或提交生产变更。

## 反馈入口与隐私

[新建反馈 Issue](https://github.com/zhiwenC125/plugins-general-dsh/issues/new/choose)：选择“安装 / 启动失败”或“内测体验反馈”。模板进入默认分支且仓库启用 Issues 后可见。

必须包含：版本、系统/架构、提供商/模型名（不含 Key）、可复现步骤、预期与实际、脱敏截图。禁止提交 Key、token URL、完整配置、私人会话、未经筛选的日志或 `.revolution` 数据目录。涉及敏感内容先通过维护者事先约定的私下渠道联系；本项目没有在这里虚构邮箱或专门的安全收件渠道。

推荐维护一张不含个人敏感信息的表：测试编号 / 平台 / 安装 / 对话 / Workflow / 重启 / 评分 / Issue 链接。不要未经同意公开测试者姓名。
