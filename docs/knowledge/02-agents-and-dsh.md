# Agent、DeepSeek Harness 与 Revolution

## 心智模型

模型负责判断和生成；Harness 提供会话、工具执行、权限、上下文与持久化；Agent 是带目标、模型配置、工具和运行状态的执行者；Workflow 用代码组织多个执行者及依赖关系；Revolution 是承载 DSH 的桌面外壳与下游插件，不是另一个大模型。

Skill 是可复用的工作说明，不天然等于执行器。MCP 是连接外部工具/数据的协议，不自动赋予安全权限。插件是应用扩展单元，可能只有服务、会话视图或 UI 插槽，不一定有独立设置页。

## 当前实现的真实边界

桌面依赖锁定 `@deepseek-ai/dsh@0.2.1-rc.2`；被忽略的 `deepseek-harness/` 源码副本可以仍是 alpha4，这两者不是同一运行环境。品牌插件使用 `conversation.hero.brand.mark` 插槽。rc.2 没有标题插槽，所以 prepare 脚本对**安装的依赖副本**做带数量校验的文案覆盖，升级不匹配就报错；不修改上游源码或用户配置。

Workflow Studio 是嵌入式插件，在会话中注册 Workflow 视图，消费真实 lifecycle 与子会话数据；没有独立设置项，也不是将原本存在的开关刻意隐藏。当前保留可见性，不新增设置入口。UI 不应把推测的依赖图、产物或成功状态伪装成运行事实。

## 一次任务如何运行

用户描述目标 → 主 Agent 理解并选择工具/工作流 → DSH 执行并持久化事件 → 子 Agent 产出文件或答案 → Workflow Studio 展示阶段、成员、状态与事实 → 用户确认导出清单。

并行适合互不依赖的调查；有前置条件的工作必须等待产物。多 Agent 不是越多越好：增加协调成本、上下文消耗和故障点。一个解释性问题通常直接回答；多来源研究加实现加验证，才值得评估分阶段执行。

## 接下来值得开发的优先级

P0：建立固定任务集，对当前 rc.2 桌面运行时运行真实端到端回归；保留事件重放、异常与取消测试。验证模型配置、恢复会话和权限确认，先于增加装饰性 UI。alpha4 源码副本仅用于对照，不作为桌面验收版本。

P1：自动 Workflow 路由先影子运行；记录建议与实际选择，允许用户否决。补预算、并发与超时策略；用真实事件做可追溯的产物血缘和失败定位。任何“重试”都必须确认幂等性，不能只画一个按钮。

P2：DSH 版本兼容探测、插件 API 合约测试、设置迁移、凭据安全存储、签名分发与更新校验。保持核心能力通过插件扩展，上游修改继续暂缓。

## 练习与术语

挑一个“搜索资料→写结论→运行测试”的任务，写出哪些部分可并行、哪些必须等待。比较单 Agent 与 Workflow 的总耗时、模型花费、成功率。再取消一个执行，确认界面不会一直显示 RUNNING。

上下文窗口：一次推理可读取的信息范围。Compaction：压缩历史，不保证保留所有细节。Checkpoint：可恢复状态，不等于重复执行外部副作用安全。Trace：执行证据链。Eval：固定输入、判定标准与测量方式构成的回归评估。
