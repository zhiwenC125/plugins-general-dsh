# Revolution 知识库与飞书机器人端到端接入方案

更新：2026-10-24。目标是让用户在 Revolution 中登录飞书后，按本人权限使用飞书普通文档和 Wiki 知识库，并能在手机飞书与自己的 Revolution 会话对话。首轮仅使用自己注册的个人飞书账号；公司飞书账号和公司资料不进入个人试验环境。

后续实施状态以 [长期记忆与飞书会话桥接](REVOLUTION-MEMORY-AND-FEISHU-BOND.md) 为准；下方“当前基线”保留制定本方案时的历史状态。

## 当前基线

- `knowledge/` 已能把同一批 Markdown 文章同步到 iCloud Obsidian、个人飞书普通文档和个人飞书 Wiki，也能从已关联的飞书文章拉回内容。5 篇文章已完成真实写入与读回校验。GitHub 保存可移植的原文和清单。
- `integrations/bot/core.mjs` 只有平台无关的消息校验与路由接口。尚无飞书消息接收、发送、持久队列和 DSH 会话调用。
- Revolution 目前只装载 `dsh-workflow-studio` 与 `revolution-brand`。知识库和机器人尚未成为应用内功能。DSH 服务绑定 `127.0.0.1`，手机不能直接访问。
- 当前飞书同步使用手动取得的 `user_access_token`。生产接入需要由应用完成授权、续期、撤销和安全存储。

## 目标体验

1. 用户在 Revolution 设置页选择「连接飞书」，通过浏览器完成飞书登录与授权；回到 Revolution 后看到已连接的身份、普通文档目录、Wiki 空间和逐项权限状态。
2. 用户选择自己的目录和空间，导入或创建文章。Revolution 可检索、引用来源、打开原文、发起同步和显示冲突；Obsidian、普通文档、Wiki 是同内容的三个并列副本，GitHub 保存原文与稳定 ID。
3. 用户在手机飞书私聊应用机器人提问；消息进入绑定的 Revolution 工作区及 DSH 会话，回答带来源链接并回到该飞书聊天。群聊首轮只处理明确 @ 机器人的消息。
4. 写文档和执行本地开发任务需按操作类型确认；普通问答只读。用户可断开连接、撤销授权、删除本地索引。

飞书登录解决身份识别和授权入口；它**不会自动授予**所有文档和 Wiki 的权限。应用权限、用户同意的范围、目标目录或空间的资源权限、机器人可用范围都必须满足。首次授权后可自动刷新凭证；新增权限时仍需用户再次同意，管理员管控的租户还可能需要管理员审批。

## 组件与数据流

```text
Revolution 设置页 ── OAuth 授权/连接状态 ── 飞书账号与权限存储
       │                                  │
       ├── 知识库面板 ── 目录/Wiki 适配器 ── 索引与来源引用
       │                    │
       │                    └── Markdown 清单 ── Obsidian / GitHub
       │
手机飞书 ── 应用机器人事件 ── 账号绑定/去重/队列 ── DSH 会话
                                                  │
                         飞书消息 API ← 结果与引用 ┘
```

知识来源和聊天入口分开实现。机器人只把已授权用户的请求交给该用户的会话；检索器在执行时按用户身份和文档权限过滤。索引保存文章 ID、来源、版本/哈希、文档 ID 和可检索文本，不保存飞书凭证或公司内容。跨来源的相同文章以稳定 ID 合并展示，但三个副本继续完整保存。

## 实施阶段与验收

| 阶段 | 开发交付 | 验收 |
| --- | --- | --- |
| 0. DSH 接口核验 | 在当前锁定的 DSH 版本验证插件服务、会话创建/输入/事件流和审批接口；写最小探针 | 能从本机受控入口启动会话、取得最终回复，不依赖模拟输出 |
| 1. 飞书账号连接 | Revolution 设置页；OAuth 授权码回调与 `state`/PKCE（按飞书当前支持方式）、凭证刷新和撤销；本机安全存储；权限诊断 | 不手动粘贴 token；重启后仍可用；过期自动续期；撤销后停止调用 |
| 2. 知识库入应用 | 将现有 `knowledge/` 逻辑抽成服务层，打包进桌面应用；目录/Wiki 选择、同步、冲突、状态、来源链接和本地全文检索 UI | 用户能在 Revolution 读、搜、同步已选普通文档与 Wiki；三处副本哈希一致；冲突不覆盖 |
| 3. DSH 知识工具 | 为会话提供检索、读取与受控写入工具；回答附文章标题及原文链接；写入进入确认和读回校验 | 本机 Revolution 聊天能引用个人飞书内容，批准后写入并重新检索到新内容 |
| 4. 飞书机器人单人闭环 | 机器人能力、`im.message.receive_v1`、长连接适配器、持久绑定/去重/队列、发送回复、任务状态 | 手机私聊提问收到真实 DSH 回答；重复事件只执行一次；断线恢复；失败有可见提示 |
| 5. 产品化与多用户 | 每人独立连接、工作区与会话；安装向导、审计、删除/撤销；部署模式验证 | A 用户无法检索或回复 B 用户数据；新用户按向导接入；移除连接后访问失败 |
| 6. 微信适配 | 按微信对话开放平台已确认协议实现适配器，复用阶段 4 的路由与 DSH 桥接 | 微信试验机器人完成同样的私聊问答与身份隔离验收 |

阶段 0 是关键技术门槛：先确认 DSH 的稳定扩展点和会话调用方式，再决定把知识工具装成 DSH 服务插件，还是由 Revolution 宿主适配器通过受支持的会话 API 调用。不要用网页点击或私有内部接口冒充正式桥接。

## 飞书授权与机器人配置

**应用所有者配置一次**：在飞书开放平台的自建应用中启用机器人，配置应用可用范围、授权回调地址、事件接收方式与消息权限，并发布生效版本。首轮个人试验可采用官方长连接，电脑需保持在线；跨租户全用户发行需另行确定商店应用、各租户自建应用或托管服务模式，不能假设个人应用天然对所有飞书账号可用。

**每位用户完成一次连接流程**：登录飞书，查看并同意文档/Wiki 所需用户权限，选择自己可访问的普通文档目录与 Wiki 空间，绑定聊天到自己的 Revolution 工作区。应用以机器人身份收发消息，以该用户授权读写其文档。两种身份的凭证与权限分别管理。用户只能操作自己本来有权限的资源。

权限应按功能分批申请：先读取身份、普通文档与 Wiki；启用同步写入时申请写权限；启用机器人时申请接收单聊/群聊 @ 消息及以机器人身份发送消息。具体 scope 以实施时官方 API 文档和后台权限页核准，避免把广泛的全租户读取权限当默认项。失效、拒绝、资源未共享、管理员未批准均应在设置页显示明确原因。

## 知识库边界与同步规则

- 首轮只接入用户明确选择的目录、空间及已有稳定 ID 的文章。现有飞书连接器只往返纯文本块形式的 Markdown；富文本、附件、评论和任意飞书文档导入需要独立解析与验收，不应显示为已支持。
- 每篇文章仍有同一个稳定 ID 和完整的三个副本。变更先检查各副本的上次同步哈希；发现双向修改即暂停写入并展示差异。写入后读回并确认哈希，再更新索引。
- GitHub 只提交允许公开或个人复用的 Markdown 和清单，不提交飞书 token、目录/空间 ID、个人索引或同步状态。公司内容始终留在公司租户与公司环境。
- 搜索结果要给出命中的文章、来源、更新时间和可打开的原文链接；索引撤销或文档权限失效后停止使用相应缓存。

## 运行模式与发布条件

第一版由本机 Revolution 保持运行，通过飞书长连接接收消息，并调用本机 DSH。Mac 关机、休眠或离线时，手机飞书无法获得实时执行；机器人应回报离线/超时状态。若要求电脑关闭后也可聊天，则需增加托管网关与任务队列，并定义云端是否可访问知识内容及本地执行权限。

面向所有 Revolution 用户前，还需完成应用发行路径、安装/授权流程、每用户凭证隔离、绑定撤销、事件签名或可信长连接校验、重放防护、限流、日志脱敏、错误恢复以及跨平台打包测试。现有个人飞书成功同步只证明该个人账号的文档和 Wiki 能用，不能替代多租户验收。
