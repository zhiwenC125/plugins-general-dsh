# Revolution 长期记忆与飞书会话桥接

更新：2026-10-24。

## 当前产品边界

- **个人知识库已实现**：每个本机 Revolution profile 有一套独立 Markdown 原文和 Obsidian、飞书普通文档、Wiki 镜像。用户的不同会话共享这套个人知识。
- **自动召回已实现**：每轮用户输入的第一个模型步骤，从本地副本自动检索最多三个带来源的片段。检索结果是资料，不是更高优先级指令；模型仍可进一步调用搜索或实时飞书读取工具。这个机制改善跨会话的事实查找，不会改变模型参数，也不能保证所有回答正确。
- **记忆写入仍需确认**：用户或模型可提议文章草稿，用户在知识库面板确认保存，之后手动同步。自动从所有聊天中提炼并写入偏好/决定尚未实现。
- **团队知识库尚未实现**：不能把当前个人本地库直接作为多人共享库。团队版需要工作区/项目范围、成员身份与 ACL、团队来源、按调用者权限过滤检索、撤权后的索引失效及审计。
- **飞书个人机器人代码已接入**：用户在设置中启用后，官方 CLI 的长连接消费私聊消息。首次仅绑定当前飞书授权账号的私聊；`/项目` 列出 DSH 工作区，`/会话` 列出其会话，选择后普通消息进入该 DSH 会话。连接、绑定、去重和选择状态存于本机。群聊与多用户未开放。

## 用户体验原则

1. 检索自动发生，但只注入少量相关片段并引用来源。用户能看到本地副本是否落后于飞书。
2. 稳定的个人偏好、项目决定和工作约束应成为可查看、可纠错、可删除的记忆条目；聊天原文不应静默变成永久团队知识。
3. 项目记忆与团队知识必须有显式作用域。个人全局、个人项目、团队项目三层检索时先按身份和项目过滤，再排序；跨租户绝不共享索引。
4. 飞书聊天始终显示当前项目和会话，切换项目时清空会话。机器人只接受可见列表中的 ID，无法借命令猜测其他用户的会话。
5. 机器人回复必须来自真实 DSH 会话执行，失败或电脑离线时给出可理解的状态；命令由确定性路由处理，不让模型猜测切换目标。

## 下一轮验收

1. 在真实手机飞书给个人应用发 `/项目`、`/会话` 和普通问题，确认事件接收、DSH 回答及飞书回复；测试断线重连、重复消息和重启后选择保持。
2. 用含已知事实的个人文章进行跨会话提问，检查自动召回命中率、引用、延迟与误召回。评估关键词检索后再决定是否增加 Embedding 和混合检索。
3. 增加“建议保存为记忆”的确认流、项目作用域选择、更新与删除；再设计团队库身份和权限模型。
4. 完成真实飞书验收后，评估公共应用发行、每位用户独立绑定、微信适配和电脑离线时的托管方案。

本地预览包的验证不等于真实飞书手机端验收或公测发行。
